# 工具总控台

一页管住这套 DSH 安装里真正在跑的东西：每个 loader 条目、每个用户技能目录里的技能。

入口有两个，看到的是同一份列表：

- 「插件」页顶部的**总控台**标签
- 侧边栏的**工具总控台**面板

## 列表里有什么

| 行 | 来源 | 开关方式 |
| --- | --- | --- |
| 插件 | 宿主的插件管理器（`pluginManager.listPlugins()`） | 写 profile 的补丁层，和「插件」页写的是同一处 |
| 技能 | `~/.dsh/skills`、`~/.agents/skills` | `SKILL.md` 改名成 `SKILL.md.disabled`（可逆） |
| MCP 服务器 | profile 的 `cordis.patch.yml` 里 `@deepseek-ai/dsh-mcp-client` 条目 | 同插件（loader）；配置改的是该条目自己的 `config:` 块 |

每行会说明它是什么、现在开没开、不能开关时为什么不能：

- **官方**：`@deepseek-ai/*` 包和 loader 自己的 `cordis:*` 条目，随客户端一起装
- **宿主托管**：插件管理器、定时器、工具注册表这类不能从外部开关的条目
- **本插件**：这个面板自己。它不允许关掉自己，否则就没有地方再把它打开
- `#1`、`#2`：同一个模块被 loader 挂了多次时的序号

## 分组

分组里可以混放插件和技能。选中一个分组后，组名下面直接给**启用 / 禁用**两个按钮，整组成员一次开关；成员超过 20 个会先问一次。

「自动分组」按规则表把现有条目分成几组：基础功能、界面与外观、创作与媒体、检索与研究、开发与运维、通知与集成、技能。它会先给预览，确认后才写；重跑只替换自动生成的那几组，手工建的组不动。

## 预设

预设记录「当前开着的这一套」。应用预设有两种：

- **应用**：打开它列出的，关掉它没列的
- **只开启，不关闭**：只补开，不关任何东西

一次要改动超过 10 项时会先确认。

## 状态存在哪

```
<DSH_HOME>/tool-hub/state.json     默认 ~/.dsh/tool-hub/state.json
```

写入是原子的（临时文件 + rename），中途崩掉不会留下半个状态。删掉这个文件等于清空分组和预设，插件与技能的开关状态不受影响。

沙盒或测试 profile 想完全隔离，可以设两个环境变量：

```
TOOL_HUB_STATE_FILE=<dir>/tool-hub-state.json
TOOL_HUB_SKILL_ROOTS=<dir>/skills;<dir>/skills2   # Windows 用分号分隔
```
